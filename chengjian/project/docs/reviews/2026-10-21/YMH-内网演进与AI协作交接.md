## 3. 四条演进方向

### I1：连接策略与路径状态

现有任务上游主要按“最新的 alive SOCKS”选择；任务代理仍与抓包开关联动。连接失败仍可能使用旧兼容回退，尚无统一的目的地策略、固定版本与依赖失败合同。

架构评估应明确：连接选择依据、适用范围、DNS/协议能力、验证时间与有效期、来源和依赖版本；指定策略失效应与允许默认出口的操作区分。入口监听正常不等于目的服务可达，不同路径的观察不能无条件合并。

本交接不提供新增远端 Shell 转发、多级控制链或自动横向移动的实施任务。I1 在此阶段交付现状评估、策略/诊断数据合同和受控本地网络 fixture 的测试设计。

### I2：能力描述与执行结果诚实性

先如实描述现有驱动，保留 Session 接口兼容。采用可选能力接口；旧驱动保守返回 unknown。

能力描述区分：驱动实现、当前环境确认、未知或不支持。包括操作支持、OS/架构证据、输出流是否分离、退出码是否可用、作业跟踪和取消语义。具有 Exec 方法不能证明远端可执行，也不能把 API 成功解释为退出码 0。

当前语言/驱动类型不能当真实 OS/架构证据；部分 platform 值来自默认赋值。当前取消本地等待也不能证明远端作业已停止。能力元数据读取不得隐式调用 Test/Exec 或产生目标侧副作用。

### I3：带来源的拓扑与认证观察

保持发现、推断、实际验证的区分。观察应引用可读取原文、内容哈希、采集来源、时间和适用范围；本地监听、网卡归属和远程服务可达性分别记录。

认证结果必须限定主体、凭据引用、服务、目标、方法、时间及适用环境。一个服务的成功不能升级为所有服务成功；失败、连接异常与未知不能混成无权限或目标不存在。凭据本体不进入上下文摘要或普通日志。

此阶段可实现观察结构、来源核验与展示，使用合成 fixture，不新增探测命令、凭据尝试或协议执行能力。

### I4：资源授权、引用及生命周期

首批只修了现有隧道运行时的部分生命周期。还需补齐授权、共享引用、运行租约、依赖和清理确认之间的边界。

先完成资源访问控制与状态诚实性，再设计任务终态 drain、引用释放及启动对账。授权表示谁可以操作；引用表示谁仍依赖；租约表示当前运行占用。不能用任一个字段替代另外两个。

## 4. 本轮只读复审确认的具体问题

### 4.1 会话 ID 查找未接通任务授权

`db/sessions.go` 已持久化 CreatedByTask/CreatedByIntent，但 `server/session.go` 的 lookupSession 当前只按全局 ID 查 Registry。执行、文件读写、侦察及隧道相关入口均需审查。`server/tunnel.go` 的 teardown 也未在工具入口检查权威 TaskID。

开发目标是统一的上下文访问检查，先验证数据库权威归属、状态及明确授权，再访问驱动。失败时不能执行驱动副作用；不能用列表按任务过滤代替操作授权。

普通聊天的 TaskID 为 0，不能自动视为管理员。人工 HTTP 管理面目前是全平台 JWT 管理入口，不等同于 AI 的任务权限；task_id 查询参数也只是过滤条件。

### 4.2 直接要求同任务会破坏现有移交

`server/handoff.go` 当前建立 SourceTaskIDs 和 ParentRef，但没有独立的具体资源 grant。任务来源继承不应自动授予全部会话权限。

授权加固需同时设计既有移交兼容：具体资源、被授权任务、允许操作、来源、撤销和有效期。保留原有经过授权的人工移交流程；新任务的创建与必要授权应保持原子性，授权失败不能启动任务。只读继承不能替代授权，历史数据也不能默认向所有任务开放。

### 4.3 取消或预算耗尽可能被写成远端 dead

审查 `server/session.go` 的 startupProbeStale 和 `server/intranet.go` 的人工探活：平台取消、等待超时、目标明确不可达应分开处理。未完成观察不能写成已确认死亡。

当前 session.Error 没有 Unwrap；仅使用 errors.Is 判断取消可能漏掉包装后的错误，应结合调用 ctx.Err()，并设计兼容的错误原因合同。

### 4.4 失败操作仍可能刷新成功心跳

部分 session_exec/read 在判断错误前 Touch。应分别记录 last_attempt 与 last_success，或最小修复为只在真实成功后更新现有成功心跳，避免失败会话持续显示新鲜。

### 4.5 清理返回值不能证明远端状态

保留 cleanup_pending 和未确认清理台账。检查 reverse Close 吞掉上游错误等边界，不能由 nil 返回推导远端已清理。超时只说明平台停止等待；未知状态需可见并可对账。

## 5. 建议分给其他 AI 的任务

| 任务 | 文件职责 | 交付与验收 |

| A：资源访问控制 | db 资源授权、server session/tunnel 工具入口和既有 handoff 兼容 | 同任务正常；无关任务拒绝且无驱动调用；合法既有移交有明确权限；撤销生效；普通继承不授权；DB 失败拒绝操作 |

| C：状态与清理诚实性 | server 探活/心跳、session 错误原因和清理回执 | 取消不误标 dead；失败不刷成功心跳；未知清理保留台账；重复停止幂等；不回归已修停止/巡检竞态 |
| D：观察来源与诊断 | 观察结构、原文引用、状态展示、本地 fixture | 推断不自动成为已验证；原文/hash 可核对；失效有原因；无新增目标探测或认证尝试 |
| E：独立复核 | 只读审查与集成测试 | 每模块完成后检查调用链、兼容性、并发、取消、数据迁移与失败路径；作者不作为唯一验收人 |

A 的授权合同先确定；B 可独立实施；C 在授权接线明确后集成。I1 的架构评估可并行，但不要在权限/状态合同未定时重写全部网络接线。多人共用目录时明确文件所有权；同一文件不能并行改，接口变更先通知集成者。
