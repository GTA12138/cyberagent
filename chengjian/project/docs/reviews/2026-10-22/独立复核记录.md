## 已完成的模块审查

- `session/capabilities.go`、`capabilities_http.go`：通过。能力描述为可选接口，兼容旧 Session；旧驱动和 typed nil 保守返回 unknown。HTTP 描述仅生成值快照，不读取可变探测状态、连接参数或 secret，不调用 Kind/Test/Exec，也不发网络请求。驱动支持与目标环境支持分开，不以语言默认值推断 OS/架构，不把本地取消视为远端停止。
- `server/session_capabilities.go` 及列表接线：通过。reverse receiver 的 typed nil 保护存在；Agent 列表先通过授权范围筛选，再读取能力。能力描述不授予资源权限。
- `db/session_access.go`、`server/resource_access.go`、`server/session_grants.go`：静态审查通过。Session 的六种 action 分别校验；TaskID0 不具备管理权限；授权数据库不可用时拒绝执行；管理 API 保持既有 JWT 边界，与 Agent 操作分开。
- `db/tasks.go`、`db/schema.sql`、`server/handoff.go`：静态审查通过。普通 SourceTaskIDs 只继承背景；人工 Handoff 的精确 session grant、parent_ref 和单主机 scope 与新任务在同一事务提交。IPv6 使用 /128，失败不遗留半成品任务。
- Tunnel 父资源与 teardown：静态审查通过。先校验当前任务归属，再进入可能取消部署或进行清理的生命周期操作。
- `tunnel/health.go`、`server/tunnel_redeploy_access.go`：静态审查通过。自动重部署前重新读取持久 tunnel/plan，验证 owner、session 和清理状态，再检查当前精确 `tunnel_deploy` 权限。撤销、过期、归档、数据库不可用或计划不一致均不会进入驱动，也不消耗部署次数；授权完成后再次检查 context 取消。显式 Teardown 不受此部署回调限制，保留清理路径。
- `db/session_page.go`、`server/session.go` 分页：静态审查通过。先授权再稳定 ID 排序和 LIMIT/OFFSET；默认 25、最大 50，查询不读取 secret。SQL 在传输前完整省略超长原子字段，工具对单条能力快照限 2048 字节、总 JSON 限 64KiB，预算缩页时只按实际输出数量推进 `next_offset`。偏移基于当前台账，不声明并发变更期间为不可变快照。
- `taskIntranet`、`snapshotSessions`：静态审查通过。共享 grant 纳入元数据可见性，不解密 secret；alive 过滤在数据库内完成。摘要已改为明确的当前展示观察，不把前 5 条 dead 等同于所有会话失效，也不把 tunnel 台账 alive 等同于任意目标可达。
- `.build/run-intranet-stability-pg.ps1`：隔离审查通过。仅允许项目内未存在的新 cluster 路径、loopback 随机端口；测试进程同时覆盖配置路径和 DSN。嵌套 finally 保证停库异常时仍恢复双环境变量，停止后用 pg_ctl status 确认未运行。

## 审查发现与复核

1. reverse listener 原先会因其他任务复用而覆盖 owner，后续新会话可能归属错误任务。现已禁止跨任务隐式移交，并使用 ensureMu 串行化懒启动；同任务复用保留原 owner。
2. register_session 和 reverse_listen 原先允许缺少任务上下文时发请求或创建资源。现已在副作用前检查明确且仍有效的任务上下文。
3. 授权列表的 PostgreSQL TEXT[] 不能直接通过 database/sql 扫描到 []string。最终实现使用 JSON 投影再反序列化；首轮全新 PostgreSQL 的 db 包通过。
4. grant 管理原先为确认存在而解密 secret，损坏 secret 会阻止撤销已加载会话的共享权限。现已改用不含 secret 的 Health 查询；回归场景明确要求损坏 secret 后撤销成功且后续调用不触发驱动。
5. 心跳测试原先引用不存在的任务，可能被新增授权检查提前拒绝。现已改用真实 owner 任务，并检查失败驱动的调用计数。
6. 自动重部署原先可绕过共享权限撤销，现已补最终准入回调；独立本地测试确认拒绝无驱动调用、允许后驱动计数为 1、回调中取消后驱动和部署计数均为 0。
7. session_list 原先可无界增长，现已使用授权元数据分页及 JSON 字节预算，且不会把被预算裁掉的行跳过。
8. 首轮全包 PostgreSQL 回归发现旧 `TestAutoAllowKeepsDenyEnforced` 测试前提失效：IsToolEnabled 在插入规则前预热了缓存，测试直接写数据库后未 Invalidate，导致根本未匹配到新 deny。SHA256 核对确认修复前本轮基线与当前的该测试、guard.go、intercept.go、autoallow.go、db/intercept.go 均相同。仅在测试插入后刷新缓存，并增加必须命中本 fixture 的 deny/ask RuleID 与 Action 的前提断言；生产 deny 分支保持原样。管理 API 规则 CRUD 本已刷新缓存。根代理已独立批准此测试变更。
9. Handoff 回滚测试确认故障发生在最后的 grant INSERT：trigger 错误字符串必须匹配，前后 task/exploration 数相等；同时校验 parent_ref 已持久化及 IPv6 /128 单主机范围。
10. `db/credstore_test.go` 的旧 defer Close 先于 t.Cleanup，删除失败被吞，导致不同密钥的第二条测试凭据残留并污染后续 server 全局凭据列表。独立读取 before 日志确认单项 db 测试通过但残留 id/task，继而 server 场景复现 500。最终仅把 Close 改为第一个 t.Cleanup（最后执行），并明确检查两次清理错误；未放宽生产解密失败处理。
11. 第二轮全包回归已修复上述三项，但 `TestInheritedActivityDetailAndRelationDeletion` 发现 Windows TempDir 删除与存活后台写入竞争。最终仅修该 API 测试 fixture：所有目录先注册清理，传入预取消 context，收集 New 恢复的所有 task IDs；清理依次 StopTask 等待 runtime、archiveWG.Wait、删除 fixture 行、关闭 Manager、清理目录。该补丁已独立复核，未忽略目录删除错误。
12. 旧 `TestWireTools` 把 worker Bash 视为完全未装饰，遗漏既有 worker UA 提示。最终只修测试断言为 SDK 描述加 bashUANote，同时要求 planner 保持 SDK 描述；未修改生产 assembly 或工具行为。

## 验证边界

本次没有真实远端目标、真实模型、完整 Web/内网端到端演练，没有运行 race 检测，也没有部署。自动重部署撤权是后续操作准入，不是对已运行远端作业的停止保证；偏移分页不是跨请求不可变快照。原十二工作包和更多协议、路由、横向等能力并未因此全部完成，不应将本轮稳定性验收解释为整体能力方案已全部实现。
