## 结论

产品方向清楚：以任务为中心，把资产、发现、证据、流量、审批及执行台账组织成安全调查工作台。它已经具备完整管理应用的领域覆盖与明确视觉方向。当前短板主要在交互可靠性和跨页面状态契约，而不是缺少组件或缺少视觉装饰。

框架能力足以支持继续扩展：有统一 API 客户端、领域类型、状态语义、共享 UI、模块导航及独立数据源。系统设计的下一步应把“请求属于哪个筛选条件、数据是否过期、输入是否真的保存”变成统一契约；否则页面越多，局部实现越难保持一致。

视觉设计已经超过普通后台模板拼装的水平：纸面底色、蓝灰证据区、克制的边框和数字字体形成识别度，列表与分布统计能保持同一语言。可用性尚未达到成熟企业应用的稳定程度，尤其是失败反馈、文件草稿和任务上下文。

## 首轮发现及最终处置

### 1. 原 P1：保存期间新增内容被标成已同步——已修复

位置：`web/src/app/(main)/function/workspace/page.tsx:116`、`:123`、`:311`。

`saveFile` 提交当时的 `edit.content`。请求返回后，成功回调对当前编辑状态无条件设置 `dirty: false`，但文本框在保存期间仍允许输入。触发方式：输入 A → 保存 → 请求尚未完成时追加 B → A 的保存返回。界面保留 A+B，却宣告已同步并禁用保存按钮；磁盘只收到 A。后续关闭会丢 B。

建议：记录提交的文件路径与内容版本，仅在当前版本仍等于提交版本时清除 dirty；或在保存期间锁定文本输入。前一种方式更适合连续编辑。验证应使用可控制完成顺序的延迟 Promise，断言保存期间追加输入后仍保持 dirty，第二次保存提交新内容。

### 2. 原 P1：关闭文件侧栏丢弃未保存草稿——已修复

位置：`web/src/app/(main)/function/workspace/page.tsx:285`、`:319`。

界面已有“未保存的修改”，但 `Sheet` 的关闭处理直接 `setEdit(null)`。点击关闭、按 Escape 或点击遮罩，均没有检查 dirty。用户已经被界面允许编辑文件，应有明确的保留/丢弃行为。

建议：关闭前统一检查 dirty，提供“继续编辑 / 放弃修改”；在页面导航或刷新时处理相同草稿状态。可选将临时草稿保存在当前页面会话中。验证覆盖按钮、Escape、遮罩三个入口；保存中也应明确处理关闭。

### 3. 原 P2：内网切换任务时旧响应覆盖当前筛选——已修复

位置：`web/src/app/(main)/intranet/page.tsx:52`、`:65`、`:85`、`:96`、`:107`、`:155`。

拓扑、会话、隧道和凭据请求均直接写入组件状态，没有请求 generation、abort 或 taskParam 匹配检查。切换任务只清除轮询定时器。若任务 A 的请求先发后回、任务 B 的请求后发先回，A 的响应会覆盖 B 的当前视图；失败时也继续保留上一个任务的数据，没有说明来源。

此外，`hostFilter` 和 `workbenchSession` 在切换任务时没有重置（`:35`、`:36`、`:248`），旧任务的工作台仍可保持打开。这是前端上下文混淆风险，不是已证实的后端权限绕过。

建议：所有资源按 taskParam 标记 generation，丢弃过期响应；切换时清理或标记旧快照。主机过滤和工作台需要显式上下文策略：随任务关闭，或显示它实际所属的任务并保持独立。使用 A/B 响应逆序、失败后切任务、工作台打开后切任务三个场景验收。

### 4. 原 P2：读取失败混成加载或空列表——本轮四页已修复，LLM/工具页待统一

位置：

- `web/src/app/(main)/function/tasks/page.tsx:458`、`:469`、`:793`、`:953`：任务请求失败被吞掉，首次成功前统计保持加载，同时正文显示“暂无任务”。
- `web/src/app/(main)/function/findings/page.tsx:318`、`:337`、`:369`、`:388`、`:578`、`:591`、`:726`：列表/分组/统计失败没有持久 error 状态。首次失败可显示空表与零条，统计可持续“读取中”；分页失败时会保留前一页数据而没有来源提示。非排序筛选会清理平铺缓存，但分组结果、翻页和周期刷新仍需明确快照语义。
- `web/src/app/(main)/system/llm/page.tsx:811`：首次配置读取失败直接忽略，`overviewLoaded` 无法完成。
- `web/src/app/(main)/system/tools/page.tsx:373`、`:436`：读取失败主动设为空数组，随后展示“暂无系统工具，等待后端 seed”，让用户把网络故障误判成缺配置。
- `web/src/app/(main)/function/workspace/page.tsx:79`、`:226`：首次读取目录失败时仅短暂 toast，列表随后显示“空目录”。

已有可复用的正确基础：`web/src/components/console/module-overview.tsx:38` 支持 error/stale，`web/src/app/(main)/function/traffic/page.tsx:204` 实际传递失败状态；`web/src/app/(main)/dashboard/use-dashboard-source.ts:6` 让数据源独立重试并记录更新时间。

建议：把 idle/loading/success/empty/error/stale 及 dataScope/updatedAt 作为共享资源状态；首次失败显示错误和重试，刷新失败保留快照并显示其来源与更新时间，筛选变化时禁止把旧快照表现成当前结果。toast 可保留作补充，不应承担持续状态。

## 可访问性需要补验的具体点

1. `web/src/app/(main)/function/findings/_components/findings-table.tsx:184` 把原生 `tr` 改成 `role="link"`，行里还包含链接、复选框和其他控件。虽已有键盘导航处理，仍会覆盖原生表格行语义。建议保留 tr 的 row 语义，以名称链接作为主要入口；全行点击只作为鼠标便利行为，并用屏幕阅读器验证表头关联。
2. 工作空间编辑框（`workspace/page.tsx:311`）和新建文件夹输入框（`:345`）缺少显式关联标签；共享分页的页容量选择器（`web/src/components/table-pagination.tsx:61`）没有表达“每页条数”的程序化名称。添加可见 Label 或 aria-label，避免仅凭邻近文字或 placeholder 推断用途。
3. 共享表格的滚动容器（`web/src/components/ui/table.tsx:9`）没有明确键盘聚焦入口或区域名称。与 dashboard 已有的具名、可聚焦滚动区（`dashboard/page.tsx:726`）统一；用键盘实际验证横向滚动和焦点可见。
4. 搜索快捷键支持 Ctrl/Command+J，但按钮始终显示 ⌘J，空结果英文（`web/src/app/(main)/_components/sidebar/search-dialog.tsx:87`、`:143`、`:150`）。使用平台对应提示并统一中文文案，减少桌面环境认知负担。
