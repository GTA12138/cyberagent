# 服务边界与重启恢复：本轮改造

本轮把任务准入、触发投递、资源清理及 Worker 会话执行拆成可以独立验证的业务单元，同时补齐数据库迁移和单实例约束。HTTP handler 与 Agent 工具复用任务创建、准入及控制规则。

| 单元 | 承担的规则 | 主要代码 |
| --- | --- | --- |
| TaskService | 创建、FIFO 准入、暂停/恢复、失败补偿、停止后资源清理 | `server/task_service.go` |
| ExecutionService | 原 Engine 的领取/取消/执行循环，以及重启恢复 | `server/engine.go`、`server/execution_service.go` |
| TriggerService | 持久化投递、合并、并发槽、有限重试 | `server/trigger_service.go` |
| ResourceService | 会话租约登记/查询、隧道逆序拆除、最后释放租约 | `server/resource_service.go` |
| Worker 会话核心 | 会话恢复、人工输入去重、执行及事件输出 | `agent/worker_execution.go` |

`service_wiring.go` 负责把现有 Manager、Engine 和资源适配器接到服务。TaskService、TriggerService、ResourceService 通过小接口依赖仓储/执行能力；Worker 核心只需要会话接口和一个结构化请求。独立测试不启动 HTTP，也不连接真实模型或远端目标。

这是一轮增量拆分。Manager 仍是兼容现有存储与运行时的适配器；Worker 的工具集、提示词及目标资产准备仍使用现有 Store。`Engine` 保留为 `ExecutionService` 的类型别名，既有调用方无需一次性迁移。后续可继续按业务单元迁出模型路由、归档编排及任务准备逻辑。

## 实例所有权与执行恢复

服务端在迁移、种子写入和运行恢复之前，先用专用 PostgreSQL 连接取得实例 advisory lock。第二个遵守此协议的服务进程会直接启动失败。实例锁与迁移、企业范围及证据锁使用不同编号。锁连接失效或主动关闭时通知运行时取消；所有权失效后的 API 返回 503，等待重启重新取得所有权。

首次升级需要先停止旧版本进程，因为旧版本尚不遵守实例锁协议。当前方案约束一个数据库对应一个服务实例；尚未实现多实例执行者租约、心跳接管或外部系统 fencing。连接检测和 Context 取消属于协作式停止，无法强制撤回已发出的远端动作。

任务内、被工具声明为有副作用且带调用 ID 的调用会经过 `AttemptJournal`：先持久化调用身份及参数哈希，再执行工具，最后持久化结果。相同调用身份已完成时返回已保存结果；参数发生变化则拒绝复用身份。

| 状态 | 含义与行为 |
| --- | --- |
| started | 执行已登记，尚未确认结果；重复进入不会再次执行 |
| completed | 已保存结果；相同调用可返回缓存结果 |
| unknown | 中断、取消或错误使执行结果无法确认；阻止该意图的新副作用调用 |
| not_executed | 人工核对确认未执行；允许再次尝试原调用 |

重启时将遗留 started 记录转为 unknown；相关 running 意图转为 blocked，其他 running 意图才恢复为 open。旧版本中有 tool_use 而无 tool_result 的 Worker 调用也会生成待核对记录。调度领取同时检查执行记录，手工把节点改成 open 也不能绕过未结算记录。主会话没有意图 ID 时，按其会话身份检查未知结果。

任务概览提供“执行结果待核对”。确认“已完成”或“未执行”都必须填写依据，并保留核对记录；核对本身不会自动恢复意图。接口为：

- `GET /api/tasks/{id}/execution-attempts`
- `POST /api/tasks/{id}/execution-attempts/{attempt}/resolve`

这是调用级恢复保护，不能保证业务动作在外部系统中 exactly once。工具自身的只读声明、调用身份以及具体外部动作的幂等能力仍然重要；任务外的独立会话尚未纳入这个任务执行账本。若持久化完全不可用，结果可能停留在 started，重启后进入待核对流程。

新归档格式为 v4，执行记录随任务一起打包及恢复，仍支持读取 v1–v3。存在 started/unknown 记录时拒绝归档，防止压缩热数据时丢失恢复依据。旧程序不能读取新生成的 v4 归档。

## 触发与资源语义

业务状态变更、`trigger_events` 事件快照和每个启用触发器的 `trigger_deliveries` 在同一数据库事务内提交；不再依赖任务/节点/活动 ID 水位。定时投递与 `last_fire` 更新也在同一事务完成。TriggerService 使用持久化领取、租约续期、尝试编号隔离旧执行者，并保留会话 ID。未开始执行的中断可以重新排队；已经进入执行且结果不明的投递保留为 failed，等待核对。详细语义和新增验证见 [事件投递、工具策略与 SSE 修复](event-delivery-tool-policy-sse.md)。

资源收尾使用独立且有上限的 Context，客户端断开不会中断收尾。隧道按 ID 倒序拆除，跳过 stopped；如果拆除失败或无法列出隧道，保留本任务会话租约并返回失败项，确认清理后重试释放。其他任务的租约不受影响。逆序是现有资源模型的近似依赖顺序，还没有显式依赖图；删除成功后的清理失败仍需根据返回的资源 ID 进行运维核对。

## 数据库与前端

迁移入口使用 `schema_migrations(version,name,checksum,applied_at)`。v1 冻结旧 schema，首次接管旧库时执行一次兼容基线；v2 接管模型记录表；v3/v4 分别增加执行账本、触发投递；v5 增加事务事件、收件人快照、租约和执行状态。后续启动只执行缺失版本，校验已执行 SQL 的 SHA-256，并拒绝比二进制更新或存在缺口的版本记录。每个迁移使用独立事务，失败不留下该版本的半份 DDL；保留死锁重试。

以后增加 `db/migrations/0006_*.sql` 并登记版本，禁止修改已经发布的迁移。`db/schema.sql` 保留为历史 schema 及旧测试工具的参考，修改它不会自动升级生产数据库。

`config.example.json` 增加连接池和超时参数：默认最大打开 16、空闲 4，连接 5 秒、查询 30 秒、迁移 120 秒。运行时至少需要 2 条连接，其中 1 条保留给实例锁。迁移和种子数据在同一专用连接上完成，种子使用该连接的事务；普通初始化即使只有 1 个连接槽也不再等待自己。运行连接设置 statement/lock timeout、空闲事务超时和连接寿命。任务创建、意图查询/领取、SSE 回放及新增账本/队列接口已开始传递 Context；其他旧 DAO 仍需逐步迁移。

前端任务数据请求及轮询迁至 `use-tasks-data.ts` / `serial-poller.ts`，请求串行，主动刷新使旧响应失效，卸载后不提交结果。会话 SSE 的换票、关闭、退避、游标推进迁至 `activity-stream.ts`；每次连接失败都主动关闭旧连接并申请新票据。会话分桶、去重及缓存裁剪迁至 `task-session-state.ts`。展示组件的进一步拆分可以继续进行。

执行记录 DTO 通过 `go run ./cmd/api-types` 生成 TypeScript 类型和实际 Go JSON 样本。Go 测试检查生成物同步，浏览器解析器和 Node 测试验证响应形状。当前契约保护覆盖新增接口，原有全部 API 尚未生成类型。

- `scripts/test.ps1`：在独立临时 PostgreSQL 集群运行 Go vet、全量 Go 测试、TypeScript 检查及 Node 测试，不使用项目运行数据库。
- 数据库用例覆盖旧库接管、迁移回滚/校验、第二实例拒绝、业务锁可用、小连接池种子写入、锁连接丢失、未知结果隔离、人工核对、归档往返及触发持久化。
- 服务用例直接验证 FIFO、暂停提交失败补偿、触发并发/重试与资源清理顺序；Worker 用例使用假会话验证脱离 Store 的执行及恢复失败处理。
- 前端用例覆盖过期响应、卸载、换票重连、重复事件、未读计数及历史阅读时的裁剪。
- 后端编译与前端静态构建单独检查；这些验证不代表已经进行真实模型或远端动作的端到端测试。
