# 事件投递、工具策略与 SSE 修复

## 事务事件与触发投递

新增增量迁移 `0005_trigger_outbox.sql`，保留 v1–v4 的原始校验值。PostgreSQL 行触发器覆盖任务创建、状态进入 timeout、finding 创建、goal 进入 met，以及工具结果写入。业务行、不可变事件快照和当时启用的每个触发器的投递行在同一事务提交；写事件或投递失败，业务写入也失败。重复写入相同 timeout/met 状态不会重复产生事件；状态离开后再次进入则是新事件。

事件 ID 只用于身份识别和排序，消费者不再保存“已经看过的最大 ID”。因此，早创建的任务后超时、低事件 ID 的事务后提交，都有独立的持久化收件人，不会越过游标丢失。旧的跨表扫描接口和超时任务 ID 水位逻辑已移除。

投递唯一键为 `(event_id, trigger_id)`，另外保留 `event_key` 以兼容手工入队及已有队列。事件保存任务上下文与消息配置快照，配置后续编辑不会改变已有投递；新启用的触发器不会补发启用前的历史事件。定时调度使用行锁，在同一事务创建事件、投递并更新 `last_fire`。

通用消费者保留既有串行/并行与合并策略。verifier 的 finding 投递仍进入 `finding_checks` 管线，并把派发错误返回给消费者，不再记录日志后当作成功消费。

| 情况 | 处理 |
| --- | --- |
| 无可用 ChatAgent | 保留 pending，不领取、不消耗尝试次数 |
| 正常领取 | 状态 running，尝试编号递增，90 秒租约；每 30 秒续期 |
| 运行前发生可确认的失败 | 最多 3 次尝试，5 秒起递增退避 |
| 领取后、进入执行前进程退出或租约过期 | 在预算内重新排队 |
| 已进入执行后进程退出、租约过期或结果不明 | 保留 failed 和原因，人工核对后处理 |
| 旧执行者续期或回写新领取的结果 | 通过状态、尝试编号和租约校验拒绝 |

通用触发会话创建后将 ID 写入投递的 `conversation_id`，用于核对结果；verifier 会话通过既有 `finding_checks` 记录关联。已经执行的外部动作不能由消息队列提供全局 exactly-once 保证，因此结果不明时不会自动重放整段会话。失败历史保留在数据库，目前没有新增投递管理页面。排查可联查 `trigger_deliveries` 与 `trigger_events`，关注 state、attempts、last_error、execution_started_at、conversation_id。

升级保留原有 pending；旧 running 因无法证明是否已执行，按结果不明保留。迁移不会自动重放迁移前的业务历史：旧内存队列或旧水位已经丢掉的事件缺少可靠消费证据，需要根据业务记录单独核对，避免重复执行外部动作。事件及投递历史保留，尚未增加自动清理策略。

## 工具策略读取失败

`Runtime.ToolResolve` 和 `AugmentTools` 显式返回错误；`wireTools` 使用调用方 Context 查询策略，查询失败返回空工具集及错误。查询成功且没有匹配配置行时，仍按既有的未托管工具规则处理；这与读取失败是两条不同路径。

Worker、Planner、MainAgent、Chat 在工具装配失败时结束本次运行，MCP 等装配资源仍执行 cleanup。Worker/Planner 由执行服务暂停任务并持久化 paused，未执行意图保持可恢复；策略错误不会进入模型错误重跑。恢复需要经正常任务恢复入口，并重新成功读取策略。策略失败时不会调用模型或工具。

## SSE 慢客户端

256 条缓冲满后，广播器关闭该订阅并发出 resync 信号。流处理在回放及实时发送前检查信号，结束连接；健康订阅继续接收。取消订阅与溢出使用同一把锁移除并关闭通道，重复 unsubscribe 不会再次关闭。

每帧设置 15 秒写入期限并检查写入、Flush 错误，避免客户端不读时一直阻塞。前端继续使用已有的错误关闭、换票、退避及游标恢复逻辑。重连时以 Last-Event-ID 优先，从持久化活动记录分批补读，每批 500 条。

## 验证

使用 `scripts/test.ps1` 的独立临时 PostgreSQL，不访问运行数据库。回归覆盖：逆序超时、事务回滚、事件写入失败回滚业务状态、事件 ID 与提交顺序逆转、finding/goal/tool 收件人、工具筛选异常、定时去重、无 Agent 时排队与消费者重建、租约过期与旧执行者回写拒绝。

服务验证覆盖工具策略失败后零模型调用、任务暂停与意图恢复；SSE 验证覆盖慢订阅溢出、健康订阅隔离、并发取消，以及阻塞客户端后连续产生 700 条活动、重连跨批次完整补读。
