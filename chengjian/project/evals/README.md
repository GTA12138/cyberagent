# 本地评测入口

`scenarios.json` 登记第一批六个验收场景。五项已经绑定可执行测试，一项是明确缺口；不把缺口标成跳过后通过。尚未形成方向文档提出的全部 26 个场景。

从项目根运行 `./evals/run.ps1`，会为已实现的场景创建独立 PostgreSQL 集群，测试后停止集群，结果保存在 `.build/verification/<本次运行>/`。`-RequireAll` 会在存在缺口时返回失败。完整工程回归用 `./scripts/test.ps1`，包含 Go vet、Go 全量测试、前端类型检查和 Node 测试。运行环境路径可通过该脚本参数覆盖。

范围：使用本机 HTTP 服务、假驱动及隔离数据库。E03 是路由模型的单元回归，E04 是能力准入回归；它们不能代替真实多网段网络和 Windows 远端主机验证。E02 实际运行本地 HTTP 代理与资产回灌，无模型调用、无外部站点、无漏洞利用。授权站点实测和端到端自主执行效果不在这些结果中。

`summary.json` 分别记录 Go 测试通过与跳过数量；`go-test.jsonl` 保留逐用例输出。跨平台测试和依赖外部环境的用例可能跳过，应在交付报告解释，不能把包级绿色当作所有场景通过。
